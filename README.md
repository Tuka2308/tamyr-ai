# TAMYR AI

**Находит не то, что ученик не знает, а то, почему.**

Адаптивные системы при ошибке упрощают задание внутри темы — пробел остаётся на месте.
TAMYR при ошибке **спускается вниз по графу предпосылок**, на предыдущие классы, до первого
навыка, которым ученик владеет уверенно. Это и есть **корневой пробел**. Дальше траектория
строится снизу вверх.

> Ученик 7 класса не решает линейные уравнения. Обычная система даёт уравнения полегче.
> TAMYR находит, что реальный корень — «действия с обыкновенными дробями», 6 класс,
> и ведёт оттуда. В нашем графе этот узел блокирует **80%** программы 6–8 класса.

**Прод:** https://tamyr-ai-pi.vercel.app · **Код:** https://github.com/Tuka2308/tamyr-ai

### Ключевое архитектурное решение

**Маршрут детерминированный. LLM не участвует в решении о том, куда вести ученика.**

[`lib/diagnose.ts`](lib/diagnose.ts) — бинарный поиск по топологически упорядоченной
цепочке предпосылок, лимит 15 вопросов. Полная история шагов (вопрос → ответ → решение →
интервал `[lo, hi]` до и после) экспортируется и показывается на `/diagnose` как «путь
диагностики». Объяснимость видна на экране, а не только в коде.

LLM отвечает **только** за объяснение уже выбранного узла. Это отделяет продукт от чат-бота.

Реализован как чистый редьюсер (`startDiagnosis` / `submitAnswer`): состояние сериализуемо,
один и тот же код крутит и интерактивный экран, и тестовый прогон. Функция `diagnose()` —
тонкая обёртка с сигнатурой из спецификации.

**Адаптивный критерий владения.** У узла ≥2 задания — 2 верных подряд, `confidence:
"verified"`. У узла одно задание (52 из 75) — достаточно одного верного ответа, но
`confidence: "single_item"`. Слабое свидетельство не выдаётся за сильное: в UI такой узел
рисуется пунктиром.

**Классификатор языкового барьера — трёхзначный.** `detected` · `not_detected` ·
`not_assessed`. Последнее означает «проверить было нечем» (у узла нет парного задания)
и нигде не сводится к `not_detected`: смешение этих двух состояний завысило бы метрику.
При обнаружении барьера ученик **не** опускается по графу — подвело условие, а не тема.

**Уточняющий проход.** Кандидат, к которому сошёлся бинарный поиск, не возвращается сразу:
сначала напрямую проверяются его непосредственные предпосылки. Если хоть одна не освоена —
настоящий корень ниже, кандидат сменяется, проверка повторяется.

Проход нужен потому, что бинарный поиск требует монотонности предиката «владеет узлом»
вдоль цепочки, а топологический порядок её не даёт: цепочка перемежает независимые ветви
программы. Без уточнения алгоритм останавливался на узел выше настоящего корня.
Уточнение идёт строго по рёбрам «A нужен для B», где неоднозначности порядка нет
по определению.

#### Измеренные характеристики (10 синтетических профилей)

| Метрика | Порог успеха | До уточнения | После уточнения |
|---|---|---|---|
| Root Hit Rate | ≥ 8/10 | 8/10 | **10/10** |
| Медиана вопросов до корня | ≤ 9 | 8 | **8** |
| Доля упёршихся в лимит | ≤ 20% | 0% | **0%** |
| Экономия на переборе | ≥ 1,5× | 1,43× | **1,28× — порог не взят** |

На полной выборке из 554 пар «цель × истинный корень» точность выросла с **77,1%**
до **99,8%**.

Пороги не пересматривались после получения результатов, профили не переотбирались.
Размен «точность за число вопросов» признан сознательным. Разбор —
в [`docs/preregistration.md`](docs/preregistration.md), раздел «Результаты замеров».

### Индекс глубины пробела (ИГП)

```
ИГП = (D + B + C) / 3 ∈ [0, 1]

D = min(1, (класс_ученика − класс_корня) / 5)          глубина
B = не_освоено_на_уровне / всего_узлов_уровня           широта
C = |потомки(корень)| / |узлы выше по программе|        блокирующая центральность
```

| ИГП | Трактовка |
|---|---|
| 0–0,25 | нет проблемы |
| 0,26–0,50 | точечный пробел |
| 0,51–0,75 | глубокий корневой пробел |
| 0,76–1,0 | системный, сигнал учителю |

В UI показывается разбивка на D/B/C, не только итоговое число.

### AI-модуль `/api/explain` (день 5, архитектура зафиксирована)

Три прохода:

1. **RETRIEVAL** — фильтр чанков по `nodeId` + лексическое ранжирование.
   Векторный поиск на 15 чанках избыточен.
2. **GENERATION** — системный промпт: только факты из переданных чанков; при нехватке —
   сказать прямо, ничего не додумывать; язык пользователя (kk/ru/en); уровень **класса узла**,
   а не класса ученика; разбор конкретного `misconception`.
3. **VERIFICATION** — второй вызов со структурированным выводом
   (`output_config.format`, JSON-схема) проверяет, что каждое утверждение опирается
   на чанки → `{ grounded: boolean, unsupported: string[] }`.
   **Если `grounded === false` — генерация не показывается, показывается исходный чанк.**

Рядом с объяснением — маркер источника: «Основано на разделе программы: …».

#### Порядок разрешения запроса

| Условие | Ответ |
|---|---|
| Чанков по узлу нет | честная заглушка «материала пока нет», генерации нет |
| Есть в кэше | мгновенный ответ из `explain-cache.json`, работает офлайн |
| Кэш-промах + есть ключ | полный тройной проход вживую |
| Кэш-промах + нет ключа | исходный чанк программы как есть |
| Верификация отклонила | исходный чанк + список неподтверждённых утверждений |

Фолбэк на чанки соседнего узла **не реализован сознательно** — это ровно то
додумывание, которое архитектура запрещает.

**Язык.** Интерфейс всегда на языке пользователя. Если чанков на его языке нет
(сейчас это всё, кроме `frac_operations` на kk), показывается объяснение из русского
источника с явной подписью «Источник на русском — перевод для этого узла пока не готов».
Молча переключать язык мы не будем: это то же самое умолчание о нехватке данных,
против которого построена вся архитектура.

**Происхождение кэша.** 14 записей `data/explain-cache.json` написаны **командой**
строго по фрагментам программы — на момент сборки доступа к API не было. Каждая
проходит офлайн-проверку заземления (`npm run validate:cache`): все числа и формулы
прослежены до источника. Живой тройной проход реализован полностью и проверен против
мока Messages API, но на реальной модели не прогонялся. `npm run generate:cache`
заменяет записи машинными при наличии ключа.

**Почему заземление важнее выбора модели.** Казахский — low-resource язык для LLM.
По данным *Information* (MDPI, 16(11):943, 2025): KazLLM-8B closed-book даёт answer
correctness **0,427**; с идеальным контекстом RAG — **0,867**; end-to-end RAG-пайплайн —
**0,754** против **0,632** у GPT-4o. Разрыв закрывает не модель, а грамотный retrieval.

**Почему ИИ не решает, куда вести ученика.** Маршрут считает детерминированный алгоритм,
и это не осторожность, а требование задачи: диагноз, который нельзя объяснить по шагам,
учитель не примет, а ученику он ничего не даёт. Интервал бинарного поиска `[lo, hi]`
показывается на экране до и после каждого ответа — это и есть объяснение.

**Почему верификация вторым вызовом, а не самопроверкой.** Модель, проверяющая
собственный текст внутри одного ответа, склонна его подтверждать. Проверка идёт отдельным
вызовом со структурированным выводом (`output_config.format`), и её вердикт имеет право
отменить генерацию: при `grounded: false` школьнику показывается исходный фрагмент
программы, а не сгенерированный текст.

**Почему видно, что ИИ сделал.** Панель «след ИИ» показывает число найденных фрагментов,
разбираемую ошибку и вердикт верификации. Это работает и в обратную сторону: когда
проверка не пройдена, панель об этом говорит и перечисляет неподтверждённые утверждения.

## Экран сравнения и «след ИИ»

### Симулятор наивной системы

[`lib/naive-baseline.ts`](lib/naive-baseline.ts) прогоняет **того же ученика** через
правило «при ошибке дай задание полегче в той же теме». У симулятора намеренно нет
доступа к графу предпосылок — только целевой узел и задания на нём. Бюджет тот же,
15 вопросов.

| На демо-профиле | Наивное правило | TAMYR |
|---|---|---|
| вопросов | 15 | **8** |
| узлов пройдено | 1 | **4** |
| классов вниз | 0 | **2** |
| причина найдена | нет | **да** |

**Это не замер стороннего продукта.** Мы не тестировали конкурентов и не заявляем,
что кто-то работает именно так: показана разница в логике. В интерфейсе это написано
над сравнением, а не мелким шрифтом внизу. Из 15 шагов симулятора 11 помечены
`synthetic` — реальных заданий на узле четыре, дальше система продолжала бы упрощать,
и выдавать модель за данные мы не стали.

Тесты стерегут главное: симулятор **не находит корень** ни на одном из 75 узлов
и не покидает целевой узел. Иначе сравнение врало бы в выгодную нам сторону.

### Панель «след ИИ»

На `/node/[id]` рядом с объяснением раскрывается панель с четырьмя шагами конвейера:
сколько фрагментов программы нашёл retrieval, под какую ошибку строилось объяснение,
прошло ли оно verification, откуда пришёл ответ — из кэша, от модели или это исходный
фрагмент.

Все четыре значения читаются из реального ответа `/api/explain`: в него добавлены поля
`tag` и `retrievedCount` именно затем, чтобы панель не пересобирала данные из локального
состояния. Логика вынесена в [`lib/ai-trace.ts`](lib/ai-trace.ts) и покрыта тестами,
среди которых есть прямой: «два разных ответа дают разный след». Он упадёт, если панель
когда-нибудь превратится в статичную подпись.

## PWA и офлайн

Офлайн — основной сценарий для школ со слабой связью, а не бонус.

Service worker (`public/sw.js`) генерируется скриптом из графа: список 75 страниц узлов
писать руками нельзя, рассинхрон был бы тихим — узел добавили, страница офлайн не
открывается, и заметить это можно только вручную. `npm run validate:sw` подключён
к сборке и падает при расхождении.

| Что | Стратегия |
|---|---|
| Навигация | сеть → кэш → корень как последний рубеж |
| `/_next/static/*` | cache-first: имена хэшированы, содержимое неизменно |
| Прочие GET | stale-while-revalidate |
| `/api/*` | **не кэшируется**: протухшее объяснение хуже честной заглушки |

Прекэш — 88 адресов: 8 экранов, 75 страниц узлов, манифест и иконки. Клиентский резолвер
объяснений сначала смотрит в локальный кэш и только при промахе идёт на сервер; если сети
нет и там, отдаётся фрагмент программы прямо из бандла.

**Lighthouse на проде:** Accessibility **100/100** на всех страницах,
Performance 89–98, Best Practices и SEO 100.

**Проверено настоящим браузером, а не на слово.** `npm run test:offline` поднимает Chrome,
проходит весь путь, выключает сеть через CDP и проходит его заново — включая перезагрузку
страницы посреди офлайн-сессии. 29 проверок из 29 проходят и локально, и на проде.
`npm run test:a11y` закрывает клавиатуру, видимый фокус, `prefers-reduced-motion`,
описания клеток тепловой карты для скринридера и ширину строк на 1440px — 18 из 18.
`npm run test:qa` проходит приложение кликами без единой перезагрузки, проверяет
пустые состояния, подсказки тепловой карты и все три локали — 53 из 53.

**Контраст.** Яркие `root`, `vein` и `spring` дают на светлом фоне 2,97 / 1,55 / 2,00
при норме 4,5:1 — как маркеры узлов они годятся, как текст нет. Для текста заведены
тёмные варианты (`root-deep` 5,00:1, `vein-deep` 6,22:1, `spring-deep` 4,70:1),
а для подписей на тёмных слоях разреза — светлый `bedrock-light` (4,98:1 против
1,76:1 у обычного `bedrock`). Палитра при этом не изменилась: те же оттенки.

## Дизайн

Метафора — **«разрез пласта»**. Классы 5→8 — слои; чем глубже пробел, тем ниже он лежит
на экране буквально, а не метафорически. Смелость сосредоточена в графе; всё остальное —
тихое и утилитарное.

| Токен | Hex | Роль |
|---|---|---|
| `ink` | `#12141C` | основной текст, тёмный фон графа |
| `chalk` | `#EEF1F2` | светлый фон интерфейса |
| `bedrock` | `#4B5266` | заблокированные узлы, вторичный текст |
| `root` | `#FF4267` | маркер корневого пробела — точечно |
| `vein` | `#FFB627` | узел «в работе», текущий вопрос |
| `spring` | `#22C38F` | освоенный узел |

Шрифты: **Unbounded** (Display) и **Golos Text** (Body), оба с полной поддержкой казахской
кириллицы (ә ғ қ ң ө ұ ү і һ), подключены через `next/font` — self-host на сборке, без
рантайм-зависимости от CDN.

Токены объявлены как `@theme static` (Tailwind v4, CSS-first). `static` здесь обязателен:
без него Tailwind вырезает токены, на которые нет ссылок в классах, — а цвета состояний узлов
и фоны слоёв мы задаём из inline-стилей через `var(--color-…)`.

**Доступность:** адаптив до 360px (на мобильном разрез сворачивается в вертикальную ленту
слоёв), видимый фокус клавиатуры, `prefers-reduced-motion` отключает пульсацию и вибрацию,
оставляя статичную обводку — состояние узла всё равно читается.

### `data/questions.json` — 129 заданий

| Группа узлов | Узлов | Заданий на узел | Разбор дистракторов |
|---|---|---|---|
| Цепочка-позвоночник | 8 | 4 (включая пару long/short) | каждый |
| Топ-15 по `centrality` | 15 | 3 | каждый |
| Остальные | 52 | 1 | каждый |

Каждое задание размечено дважды: прозой в `misconception` (идёт в `/api/explain`
как предмет разбора) и машиночитаемым тегом в `misconceptionTags`
(`procedural` · `conceptual` · `careless` · `language_barrier`). Тег `careless`
отделён намеренно: арифметическая невнимательность **не** является пробелом
и не должна опускать ученика по графу.

**Пары на языковой барьер.** 8 пар — по одной на каждый узел позвоночника: одно
умение в длинной и краткой формулировке, связаны через `pairId`. Внутри пары
меняется **только** длина условия: верный ответ обязан совпадать буквально, иначе
разница в результатах объяснялась бы формой ответа, а не барьером. Это правило
проверяется валидатором.

### `data/curriculum_chunks.json` — 21 чанк

Покрыты три узла демо-сценария RAG: `frac_operations` (найденный корень),
`linear_equations` и `linear_equations_systems` (старт диагностики). Для корня
чанки есть и на казахском — заземление на low-resource языке и есть основной
аргумент архитектуры, так что демонстрировать его надо на казахском, а не на русском.

### `data/seed_students.json` — 25 профилей

Распределение корневых пробелов намеренно неравномерное:

| Корневой узел | Учеников | Доля |
|---|---|---|
| `frac_operations` (6 кл.) | 7 | 28% |
| `frac_common_denom` (6 кл.) | 5 | 20% |
| `fractions_basic` (5 кл.) | 2 | 8% |
| ещё 8 узлов боковых ветвей | 11 | 44% |

**Два узла держат 48% класса** — это и есть заголовок тепловой карты учителя.
Кластер дробей целиком — 56%.

Файл сгенерирован `scripts/generate-students.ts` с фиксированным seed:
повторный запуск даёт тот же файл. Генерация выбрана вместо ручной записи ради
ссылочной целостности — `rootNodeId`, `masteredNodeIds` и `questionId` в истории
ошибок обязаны существовать в графе и в наборе заданий, и это проверяется.

Валидатор (`npm run validate:graph`) падает с кодом 1 при: цикле (с печатью полного пути
цикла), ссылке на несуществующий id, дубле id, предпосылке из старшего класса, отсутствующем
переводе, разрыве обязательной цепочки-позвоночника, размере графа меньше 60 узлов.
Он подключён к `npm run build` — **битый граф не соберётся**.

### Честно о данных

Все данные в репозитории — **тестовые, составлены командой** по логике программы
математики 5–8 класса РК. Это не выгрузка из официальной базы и не результат замеров
на реальных учениках. `seed_students.json` (день 2) — **синтетические профили**,
нужны исключительно для демонстрации тепловой карты учителя; за ними не стоит
ни один реальный ребёнок. Никаких заявлений об измеренной образовательной
эффективности мы не делаем — критерии проверки зафиксированы заранее
в [`docs/preregistration.md`](docs/preregistration.md).
