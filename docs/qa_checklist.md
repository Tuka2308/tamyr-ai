# QA-чек-лист перед сдачей

Формализует практику, которая шла все дни работы: тесты писались вместе с кодом
(90 → 119 → 161 → 172), валидаторы данных подключены к сборке и роняют её.
Этот файл — то, что проверяется руками перед отправкой, поверх автоматики.

Отмечать фактическое состояние, а не желаемое. Непройденный пункт остаётся
непройденным и попадает в статус-репорт.

## Автоматика (должна быть зелёной)

- [ ] `npm run typecheck` — без ошибок
- [ ] `npm test` — все тесты проходят
- [ ] `npm run build` — проходит целиком, включая три валидатора:
  - [ ] `validate:graph` — 75 узлов, циклов нет, позвоночник на месте
  - [ ] `validate:data` — задания, чанки и профили согласованы с графом
  - [ ] `validate:cache` — числа и формулы объяснений прослежены до источников
- [ ] Ноль `console.error` в консоли браузера на каждом экране

## Сквозной сценарий — без перезагрузки страницы

Пройти целиком, не обновляя вкладку:

- [ ] `/` → кнопка «Пройти диагностику»
- [ ] `/onboarding` → 4 шага, «Назад» работает на каждом
- [ ] `/diagnose` → разрез слева, вопрос справа, скобка сужается по ходу ответов
- [ ] Переход на `/result` происходит сам после последнего ответа
- [ ] `/result` → корень, ИГП с разбивкой D/B/C, сравнение с наивной системой
- [ ] `/path` → траектория снизу вверх, все узлы кликабельны
- [ ] `/node/[id]` → объяснение, маркер источника, панель «след ИИ», задания
- [ ] `/dashboard` → корень, ИГП, прогресс, дни до ЕНТ
- [ ] `/teacher` → тепловая карта, автоприоритет, форма добавления задания
- [ ] `/about` → все шесть разделов на месте

## Состояния экранов

Каждый экран проверить в трёх состояниях, не только в успешном:

- [ ] **Пусто**: `/result`, `/path`, `/dashboard` без пройденной диагностики —
      подсказка и кнопка, а не пустая страница и не ошибка
- [ ] **Загрузка**: `/node/[id]` показывает состояние ожидания объяснения
- [ ] **Нет данных**: `/node/scale_maps` — честное «материала пока нет»,
      задания при этом работают
- [ ] `/api/explain` при `grounded: false` показывает исходный фрагмент,
      а не сгенерированный текст

## `/api/explain` в обоих режимах

- [ ] **Без ключа**: три чанкованных узла отдают кэш, остальные — заглушку,
      ни одного падения
- [ ] **С ключом**: живой тройной проход, verification возвращает
      `{ grounded, unsupported }`, отклонённая генерация не показывается
- [ ] Ключ отсутствует в `.next/static` (`grep -rl ANTHROPIC .next/static` пусто)

## Адаптив

- [ ] **360px**: разрез сворачивается в вертикальную ленту, тепловая карта
      скроллится внутри себя, страница по горизонтали не едет
- [ ] **1440px**: сплит 60/40 на `/diagnose` держится, контент не растягивается
      в нечитаемую строку
- [ ] Форма добавления задания на 360px: поля не наезжают друг на друга

## Доступность

- [ ] Клавиатурная навигация проходит весь сценарий: Tab доходит до каждой
      кнопки и варианта ответа, видимый фокус есть везде
- [ ] `prefers-reduced-motion`: пульсация узла и вибрация корня выключаются,
      остаётся статичная обводка — состояние узла всё равно читается
- [ ] Тепловая карта: у каждой клетки есть текстовое описание для скринридера
- [ ] Переключатель языка меняет `<html lang>`

## Офлайн

- [ ] Выключить сеть в devtools и пройти сценарий целиком:
      онбординг → диагностика → результат → путь → узел с объяснением → учитель
- [ ] Объяснения трёх чанкованных узлов открываются без сети
- [ ] Ничего не падает с сетевой ошибкой в консоли

## Данные и честность
