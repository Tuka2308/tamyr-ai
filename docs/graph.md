# Граф предпосылок: как он построен

## Что это

`data/graph.json` — направленный ациклический граф навыков по математике 5–8 класса.
Ребро `A → B` читается: **«B нельзя освоить, не владея A»**. Не «B идёт после A по
календарю», а именно отношение предпосылки. Это различие принципиально: алгоритм
диагностики спускается по этим рёбрам, и ложное ребро уводит ученика не туда.

75 узлов, 108 рёбер. По классам: 5 кл — 19, 6 кл — 19, 7 кл — 18, 8 кл — 19.

## Схема узла

```ts
type Node = {
  id: string;                      // стабильный, не меняется после публикации
  grade: 5 | 6 | 7 | 8;
  subject: "math";
  title: { kk: string; ru: string; en: string };
  prerequisites: string[];         // id узлов, без которых этот недоступен
  centrality?: number;             // НЕ в JSON — достраивается при загрузке
};
```

## Правила разметки

1. **Предпосылка, а не хронология.** Ребро проводится, только если навык-предпосылка
   используется в самой процедуре решения. «Проценты» зависят от «десятичных дробей»
   потому, что перевод процента в дробь — шаг решения, а не потому, что тема идёт раньше.

2. **Минимальность.** Транзитивные рёбра не дублируются. Если `A → B → C`, ребро `A → C`
   не проводится: транзитивное замыкание всё равно считается обходом в `buildPrereqChain`.
   Лишние рёбра раздувают цепочку бинарного поиска и удлиняют диагностику.

3. **Класс предпосылки не выше класса узла.** Нарушение — ошибка валидатора
   (`bad_grade_order`), а не предупреждение. Спуск по графу обязан вести вниз по программе.

4. **Ветвление обязательно.** Граф не должен быть одной длинной цепью: у 8 класса должно
   быть несколько независимых входов (алгебра, геометрия, статистика), иначе тепловая карта
   учителя показывает одну и ту же точку у всех 25 учеников.

5. **Три языка сразу.** Узел без `title.kk` или `title.en` не проходит валидацию.
   Язык нельзя «доперевести потом» — он часть схемы.

## Цепочка-позвоночник

Демо-сценарий требует непрерывного спуска глубиной 4 класса. Эта цепочка зафиксирована
в валидаторе (`scripts/validate-graph.ts`, константа `BACKBONE`) — её разрыв роняет сборку:

```
natural_numbers          5 кл  ──▶  fractions_basic          5 кл
                                          │
                                          ▼
                              frac_common_denom              6 кл
                                          │
                                          ▼
                              frac_operations                6 кл   ← корень демо
                                          │
                                          ▼
                              negative_numbers               6 кл
                                          │
                                          ▼
                              linear_expressions             7 кл
                                          │
                                          ▼
                              linear_equations               7 кл
                                          │
                                          ▼
                              linear_equations_systems       8 кл   ← старт диагностики
```

Диагностика стартует на `linear_equations_systems` (8 кл), ученик ошибается, бинарный поиск
по цепочке спускается до `frac_operations` (6 кл). Спуск через два класса — это то, чего
не делает ни одна адаптивная система внутри темы.

## Боковые ветви

Остальные 67 узлов — реальные линии программы, каждая со своей цепочкой предпосылок:

| Линия | Примеры узлов |
|---|---|
| Делимость | `nat_divisibility` → `gcd_lcm`, `prime_factorization` → `divisibility_advanced` |
| Десятичные дроби | `decimal_basic` → `decimal_operations` → `units_measure`, `rounding_estimation` |
| Отношения и проценты | `ratio_basic` → `proportion` → `percent_problems`, `scale_maps`, `direct_inverse_proportion` |
| Рациональные числа | `negative_numbers` → `rational_numbers` → `rational_operations` |
| Многочлены | `monomials` → `polynomials` → `polynomial_multiply` → `abbreviated_multiplication` → `factorization` |
| Функции | `coordinate_plane` → `function_concept` → `linear_function` → `quadratic_function` |
| Геометрия | `geometry_intro` → `angle_measure` → `triangles_basic` / `parallel_lines` → `triangle_angles_sum` → `similar_triangles` → `trigonometry_intro` |
| Статистика и вероятность | `data_tables_basic`, `average_value` → `statistics_basic` → `statistics_grouped`, `probability_classic` |

Ветвление даёт тепловой карте учителя неравномерное распределение пробелов: ученик может
уверенно решать уравнения и при этом провалиться на пропорциях.

## centrality: почему её нет в JSON

`centrality` — **производная величина**, а не факт о предметной области. Захардкоженное
число разъедется с графом при первом же добавленном узле и будет врать на защите.

Формула (`lib/graph.ts`, `computeCentrality`):

```
centrality(N) = |потомки(N)| / |узлы класса N и старше, кроме N|
```

`потомки(N)` — все узлы, транзитивно зависящие от `N`; обход в ширину по исходящим рёбрам.
Результат срезается на 1. Лист графа получает ровно 0.

Текущие значения (`npm run validate:graph`):

| centrality | Узел | Класс |
|---|---|---|
| 100,0% | `natural_numbers` | 5 |
| 83,6% | `frac_common_denom` | 6 |
| **80,0%** | **`frac_operations`** | **6** |
| 79,7% | `fractions_basic` | 5 |
| 58,2% | `negative_numbers` | 6 |
| 52,8% | `linear_expressions` | 7 |
| 38,9% | `square_root` | 8 |

Число «80% программы» в питче — не оценка, а посчитанная величина; она пересчитывается
при каждом запуске валидатора.

## Валидация

`npm run validate:graph` (подключён к `npm run build`) проверяет:

| Проверка | Код ошибки |
|---|---|
| Циклы — с печатью полного пути цикла | `cycle` |
| Ссылки на несуществующие id | `missing_prerequisite` |
| Дубли id | `duplicate_id` |
| Предпосылка из старшего класса | `bad_grade_order` |
| Отсутствующий перевод kk/ru/en | `missing_title` |
| Разрыв цепочки-позвоночника | `backbone` |
| Меньше 60 узлов | `size` |
| Топосорт покрыл не все узлы (страховка) | `topology` |

Изолированные узлы (без предпосылок и без зависимых) выводятся как `warn` и сборку не роняют.

## Ограничения текущей версии

- Граф размечен командой по логике программы, **без участия предметников** и без сверки
  с ГОСО. Это гипотеза о структуре предмета, а не утверждённая карта.
- Все рёбра равнозначны. В реальности предпосылки различаются по силе: без общего знаменателя
  дроби не сложить вообще, а без прикидки решить можно, просто хуже. Веса рёбер — следующий шаг.
- Казахские заголовки — черновой перевод, требует вычитки учителем математики.
- Один предмет. Расширение на другие — только после валидации этого.
